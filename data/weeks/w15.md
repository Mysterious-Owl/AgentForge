# W15 · ReliabilityKit™

## What it is
ReliabilityKit™ is the production-reliability layer for an LLM app: it treats a prompt change or a model swap as a deployment that must pass a frozen-set gate, and it handles bad model output without shipping it. It spans two builds - a prompt-versioning regression gate for a support-ticket classifier, and a toolkit for incident-severity extraction.

## How it works
- Prompts are files (`classify@v1..v3`, `extract@v1..v3`) carrying a content SHA; `GET /prompts` lists them, an unknown or path-shaped version is refused with 404, and a test pins every SHA so an edited prompt turns CI red.
- `POST /regression-check` and `regression_run.py` score a prompt version on a frozen 12-case golden set (four intents: billing, technical, account, other) using the model's raw answer, threshold 0.8; exit 0 pass, 1 fail, 2 unknown version, 3 cannot score.
- `POST /diagnose` is a deterministic decision tree mapping signals to one of four root causes: retrieval gap, prompt ambiguity, model mismatch, parsing failure.
- `POST /generate` enforces a Pydantic contract: strict parse, then JSON salvage, then up to 2 correction prompts given the real validation error; 3 consecutive failures trip a process-level circuit breaker (503) that half-opens after 30 s.
- `POST /upgrade-check` and `eval_run.py` A/B the production pin against a candidate on a frozen 10-case severity set: promote if delta >= 0, hold within -0.02, otherwise rollback-risk with a non-zero exit.

## Key decisions
- **Score the raw answer, not the normalised label** - a normalising gate would pass a prompt whose output contract drifted.
- **Promotion stays human** - a green gate allows a change; switching `ACTIVE_PROMPT_VERSION` is a deliberate config change.
- **Deterministic diagnosis, not an LLM judge** - same signals, same verdict, no cost.
- **Frozen sets hashed into every report** - the trade-off is that 10 cases cannot resolve a 0.02 tolerance, so `hold` is unreachable on the shipped set.

## Results
- Prompt gate on the 12-case `data/golden_set.json`: `classify@v1` 0/12, `classify@v2` 7/12 (0.583), `classify@v3` 12/12, threshold 0.8.
- Upgrade A/B on the 10-case `data/frozen_test_set.json`: `gpt-5.4-mini-2026-03-17` 10/10 vs `gpt-5.6-luna` 9/10, delta -0.1, verdict rollback-risk (logged in `UPGRADE_DECISION_LOG.md`).
- The 4th request after 3 failures returns HTTP 503, and editing one frozen row changes the set hash `cc4ef1b5a994` -> `961c18e9f53a`.

## Stack
Python, FastAPI, Pydantic 2, OpenAI SDK with `gpt-5.4-mini-2026-03-17` (candidate `gpt-5.6-luna`), GitHub Actions, pytest.
