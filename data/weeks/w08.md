# W8 · SpecialistTuner

## What it is
SpecialistTuner fine-tunes a model into a specialist on the "Attention Is All You Need" paper, two ways: a LoRA adapter on open Qwen3-0.6B trained on a laptop CPU, and a hosted supervised-tuning job on Vertex AI Gemini. It shows engineers how to train, serve and measure a domain adapter.

## How it works
- LoRA: `Qwen/Qwen3-0.6B` in fp32 on CPU (4-bit QLoRA when CUDA is present), r=8, alpha=16 on q/k/v/o = 2,293,760 trainable parameters (~0.38%).
- Training: 46 examples in `data/specialisttuner.jsonl`, split 41/5; 4 epochs, lr 2e-4, batch 1. A custom collator masks everything before the assistant header and all padding, so only answer tokens are learned; padding uses a dedicated `[PAD]` token, never EOS.
- LoRA routes: `POST /v1/fine-tune/start`, `GET /v1/fine-tune/status`, `POST /v1/chat/completions?adapter=...`, `POST /v1/eval/run` over the 42-question `data/eval_aiayn.jsonl` (pass if an accepted string appears).
- Vertex: 211 examples in a provider-neutral `{role, message}` format are converted by `POST /convert` into Gemini SFT JSONL, uploaded to GCS and tuned on `gemini-2.5-flash-lite` (4 epochs, adapter size 4, us-central1) via `POST /v1/tune/start`; `POST /predict?tuned_endpoint=...` serves it.

## Key decisions
- **0.6B on CPU, not 8B on rented GPUs** - no GPU or gated access; the recipe is identical at 8B.
- **Completion-only loss** - no gradient spent on prompt tokens.
- **Keep the best checkpoint** - `load_best_model_at_end` on eval loss keeps epoch 2 (`out/checkpoint-82`) of a run that overfits.
- **Generic data plus a converter** - vendor JSONL is a build output; switching provider is a one-file change.

## Results
- LoRA training, 5-example validation split (LoRA package, `out/checkpoint-164/trainer_state.json`): eval loss 2.268 -> 2.205 (best, epoch 2) -> 2.240 -> 2.299; train loss 2.859 first logged, lowest 1.508.
- LoRA benchmark on `data/eval_aiayn.jsonl`: 13/42 (31.0%) for `checkpoint-164`, the final checkpoint (LoRA package, screenshot `WebUI_finetuning_eval.png`); about 33% for the kept `checkpoint-82`, recorded in a live run with no saved output. No base-model accuracy run is recorded; a live side-by-side on one question only showed a weaker base answer.
- Tuned Gemini, same 42 questions (Vertex package, `week8_notebook.ipynb`): 29/42 (69.0%) - architecture 84.6%, attention 100%, regularization 66.7%, results 14.3%, training 70.0%; no base-Gemini run recorded.
- One-question latency (Vertex package, `week8_notebook.ipynb`): local LoRA 19,260 ms vs tuned Gemini 2,456 ms.
- Tests: 4 (LoRA) and 18 (Vertex), all offline.

## Stack
Python, FastAPI, Pydantic; LoRA: torch, transformers, peft, `Qwen/Qwen3-0.6B`; Vertex: google-cloud-aiplatform, google-cloud-storage, `gemini-2.5-flash-lite` (undated in code).
