# W7 · BreakRAG™

## What it is
BreakRAG™ is an adversarial evaluation harness: it treats a RAG service as a black box, attacks it with deliberately distorted questions, has two LLM judges score every answer, and turns the result into a pass/fail scorecard for CI. It is for teams that want every "it works" claim tested against hostile inputs before shipping.

## How it works
- `app/adversarial.py` expands the 10 seeds in `app/seeds/golden_set.json` into 7 cases each (seed, two typos, jailbreak, multi-hop, conflict, hostile) = 70 cases, via seeded pure-Python mutations.
- The system under test is any `POST /answer`; BreakRAG™ ships its own (Week 5 hybrid retrieval, 0.55 / 0.08 gate, `gpt-5.4-mini-2026-03-17`), with `app/query_focus.py` rewriting messages into clean retrieval queries.
- Judges `gpt-5.4-nano-2026-03-17` (primary) and `gpt-5.4-mini-2026-03-17` (secondary) score 0-5; a case passes only if the mean is >= 4.0 and the system did the expected thing (match, refuse or abstain).
- `app/scorecard.py`: per-strategy pass rates, hand-rolled Krippendorff's alpha, paired bootstrap CI (5,000 resamples), three leakage checks (8-gram, embedding above the corpus 99th percentile, canary), run manifest.
- Routes: `POST /run`, `GET /run-demo-stream` (SSE), `POST /score-one`.
- `.github/workflows/eval.yml`: offline smoke and leakage checks on every PR; nightly live run uploads the scorecard.

## Key decisions
- **Deterministic mutations** - every PR runs the same 70 cases, so the case set adds no noise; less variety than LLM-written attacks.
- **Two judges, one provider** - disagreement is cheap; the mini judge shares the SUT's model, a documented self-grading risk.
- **Exactly four CI floors** - pass rate >= 0.70 per strategy, alpha >= 0.60, at least 50 samples, leakage clean; judge disagreement is INFO only.
- **Blank scorecard over an unmeasured one** - a pre-fix RED run was withdrawn because the harness was broken.
