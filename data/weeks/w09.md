# W9 · OpsAssist

## What it is
OpsAssist is a tool-using ops agent for on-call engineers: given a free-form incident description, it looks up a runbook, queries a metrics endpoint and proposes a remediation. It is written in raw Python with no agent framework, built around a bounded loop, typed tool contracts and layered state.

## How it works
- `POST /agent/run` runs a four-step loop (model decides, tools execute, results injected with matching `tool_call_id`, stop check) and returns an `AgentResponse` with `final_response`, `iter_count`, `stop_reason` and a per-iteration `trace`.
- Three tools: `get_runbook`, `query_metrics` and `propose_remediation`; tool arguments are Pydantic models with `Literal[...]` fields (for example `window`: 5m, 1h, 24h).
- The dispatcher `execute_tool` never raises: an unknown tool returns `{"success": False, "error": "unknown_tool"}`.
- Seven stop conditions: `end_turn`, `max_iters` (10), `token_budget` (16,000 tokens, checked when under 500 remain), `cost_budget` (off unless `MAX_COST_USD` is set), `fatal_tool_error`, `consent_revoked`, `timeout` (120 s wall clock).
- Three-layer state: `ShortTermState` (one request), `WorkflowState` (Redis or in-process dict, 24h recovery hint, no `messages` key) and `PersistentState` (PostgreSQL or SQLite: consent, prefs, audit log). Passing the same `task_id` resumes from the last successful tool call.
- The OpenAI call is retried with tenacity: 3 attempts, exponential jitter 0.5-8 s.

## Key decisions
- **`Literal` types on every finite-valued tool field** - stops the model emitting strings like `auth_service` that fail silently at lookup; the cost is maintaining the enumerations.
- **Error envelope instead of exceptions** - one code path after every tool call; failures land in the trace instead of crashing the loop.
- **Idempotency key only on `propose_remediation`** - the other two tools are read-only; the key makes the one side-effecting tool safe to retry without duplicate incidents.
- **Consent read once per session, not per iteration** - zero persistent reads inside the loop; the trade-off is that a mid-run revocation is honoured on the next request.

## Results
- `eval_run.py` scores a 5-scenario golden set against a stub model (no API spend): 3/5 pass by design. Two are built to fail: `wrong-remediation` misses the expected keyword, and `needs-escalation` calls an unshipped `escalate_to_human` tool, so the loop stops with `fatal_tool_error`.
- `tests/test_endpoint.py` holds 12 offline smoke tests (dispatcher, stop conditions, id binding, idempotency, resume, state boundaries).

## Stack
Python 3.10+, FastAPI, OpenAI SDK (openai 2.14.0) with `gpt-5.4-mini-2026-03-17` by default, Pydantic / pydantic-settings, tenacity, Redis (optional), SQLite or PostgreSQL.
