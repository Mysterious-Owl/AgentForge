# W11 · AgentMesh™ + CohortMCP

## What it is
Two interoperability builds. CohortMCP is a standalone MCP tool server that any MCP host, such as Claude Desktop, can call, with an eval that measures whether a model picks the right tool. AgentMesh™ wraps the TriageFlow™ specialist as an A2A v1.0 remote agent so classmates' agents can discover it, delegate tasks to it and approve its actions over the network.

## How it works
- CohortMCP exposes `cohort_lookup(student_id)` and `incident_history(query)` on the official `mcp` SDK's `FastMCP`, over stdio or Streamable HTTP (`MCP_SERVER_TRANSPORT=http`, port 8766), reading JSON fixtures.
- Tool failures come back as `{code, message, retryable}` (`unknown_tool`, `bad_arguments`, internal) instead of a raw SDK exception.
- `GET /eval/run` sends an 8-example golden set through `pick_tool` (`tool_choice="required"`) and scores `picked_tool == expected_tool`; `TOOL_DESCRIPTION_QUALITY=good|bad` swaps the tool descriptions.
- AgentMesh™ serves an Agent Card at `/.well-known/agent-card.json` with `skills[]` (`triage_incident`, `whoami`) and `capabilities` holding protocol flags only, and stamps `A2A-Version: 1.0` on every response.
- `POST /tasks` (202), `GET /tasks/{task_id}/stream` (SSE with `Last-Event-ID` replay, 100-event buffer, an explicit `replay_gap` marker), and `POST /tasks/{task_id}/input` for approve or reject (409 if not paused; no reply in 300 s fails the task).
- JWT verification against a cached JWKS (24 h), a strict audience (`agentmesh`) and scope `triage:invoke`; structured 401/403 reasons. The MCP surface (tools, resources, prompts) is also mounted at `/mcp`, gated by scope `mcp:invoke`.

## Key decisions
- **Swappable task store** - one interface, memory (default) or SQLite (`TASK_STORE_BACKEND=sqlite`); event ids are a per-task counter so replay survives the buffer wrapping.
- **Agent core untouched** - `triage_core.py` knows nothing about HTTP, JWT or SSE; it is deterministic and calls no model at runtime (`app/llm.py` is a wired but undialled seam).
- **Nano model for tool picking** - choosing between two clear tools is a cheap classification task.
- **Card signature declared but empty** - the omission is visible rather than hidden.

## Results
- Tool-pick eval on the 8-example golden set with `gpt-5.4-nano-2026-03-17`: `good` descriptions score 8/8 (accuracy 1.0); vague (`bad`) descriptions drop it to 5/8 (62.5%).
- AgentMesh™ ships 32 offline tests and CohortMCP 8.

## Stack
Python 3.10+, FastAPI, `mcp` 1.28.1 (FastMCP), OpenAI SDK with `gpt-5.4-nano-2026-03-17` / `gpt-5.4-mini-2026-03-17`, PyJWT, sse-starlette, SQLite.
