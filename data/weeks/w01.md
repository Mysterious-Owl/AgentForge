# W1 · ReleaseBot

## What it is
ReleaseBot takes raw engineering release notes, summarises them with an LLM and emails a typed summary to the team. It is the first build of the capstone and shows three patterns reused later: token streaming, structured output validated by Pydantic, and a single forced tool call. Its baseline diagram maps it onto four layers - Model, Retrieval, Tool, Memory - of which only Model and Tool ship in code.

## How it works
- FastAPI app with routes `GET /`, `GET /health` (returns the model name), `GET /readme`, `POST /summarize` and `POST /summarize-stream`.
- `POST /summarize-stream` calls `chat.completions.create(stream=True)` through `AsyncOpenAI` and wraps each delta as an SSE frame `data: {"delta": ...}`, ending with `data: [DONE]`.
- `POST /summarize` makes one API call with `tool_choice` forcing `send_email`; the tool arguments `to`, `headline`, `bullets`, `risk_level` are the structured output, so no text parsing or second call is needed.
- The `send_email` schema uses `strict: true`, all fields required, `additionalProperties: false`, and `risk_level` as the enum `low | med | high`.
- `ReleaseSummary` (Pydantic) enforces what strict mode cannot: headline 1-120 chars, 2-6 bullets. A failed build of it surfaces as HTTP 502; a request-side error (empty `release_notes`, missing recipient) is 422.
- `send_email` sends via Gmail SMTP over SSL on port 465 and returns `{"success": false, "error": ...}` instead of raising.

## Key decisions
- **Tool arguments as the structured output** - one round trip instead of a tool call plus a second completion; the trade-off is that the email action and the summary are produced by the same call.
- **Strict schema plus Pydantic** - strict mode guarantees parseable JSON, shape and enum, but not length or item counts, so Pydantic checks those at the boundary.
- **Typed settings via pydantic-settings** - `openai_api_key`, `smtp_sender` and `smtp_password` are required, so a missing key fails at startup, and `get_settings()` is cached so `.env` is read once.
- **Dated model pin** - `gpt-5.4-mini-2026-03-17` rather than an alias; a `gpt-5.4-nano-2026-03-17` fallback field is declared in settings but no code path uses it.
- **Open CORS** (`allow_origins=["*"]`) - for local development only.

## Results
- No scored eval set this week; four offline smoke tests in `tests/test_endpoint.py` cover `/health` returning 200, an empty `release_notes` returning 422, a valid `ReleaseSummary` round-tripping and an invalid `risk_level` being rejected.

## Stack
Python, FastAPI 0.115.5, OpenAI SDK 2.14.0 with `gpt-5.4-mini-2026-03-17`, Pydantic 2.9.2, pydantic-settings 2.6.1, smtplib (Gmail SMTP), pytest.
