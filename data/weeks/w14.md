# W14 · DeployCore

## What it is
DeployCore is an SRE answer service for `billing-api` whose shipping decision is made by a pipeline: a CI eval gate blocks a deploy when answers regress, even with green unit tests. A second build moves long AI work (corpus ingestion, a nightly eval) onto a background queue and wraps each answer in an OpenTelemetry cost-and-quality trace.

## How it works
- GitHub Actions `ci.yml` runs `test -> eval-gate -> build -> deploy` via `needs:`; deploy builds a Docker image stamped with `GIT_SHA` and checks that the container serves `GET /version` (prompt version, model, git sha).
- Prompts are versioned files (`answer-v3.txt`, `answer-v4.txt`) selected by `PROMPT_VERSION`; a test fails on any unpinned model id such as `gpt-5.4-mini-latest`.
- `eval_gate.py` / `GET /eval` run the same `answer_question()` path as `POST /ask` over a 5-case golden set; a case passes if its expected citation markers appear and rule-based groundedness is at least 0.8; the gate needs a 0.80 pass rate.
- `POST /ingest` returns 202 with a job id and is polled at `GET /jobs/{id}`; a local thread queue or Celery on Redis runs the same task bodies, with 3 retries, exponential backoff, idempotent upsert by `doc_id` and a dead-letter queue (`GET /queue/stats`, `GET /queue/dead-letters`).
- `POST /batch-eval` runs the nightly eval as a job; `POST /ask` returns a span tree `ask -> retrieve_context -> llm.chat -> score_groundedness`, with `cost_usd` as a custom attribute and `gen_ai.*` token attributes.

## Key decisions
- **Gate scores the shipped path** - same function as `/ask`, at the cost of live model calls per push.
- **Rule-based groundedness, not an LLM judge** - free and repeatable scoring; a richer judge is left for a nightly job.
- **Version in the prompt filename** - rollback is a config change.
- **`acks_late` with mandatory idempotency** - a redelivered job must be safe to run twice.
- **`cost_usd` marked custom, `gen_ai.*` semconv** - enforced in code; cost uses a toy price table.

## Results
- `answer-v4`: pass rate 1.00 (5/5, each case groundedness 0.95) against 0.80 on the 5-case `data/golden_set.jsonl`; `answer-v3`: 0.00 (0/5), so the gate fails and blocks the deploy.
- Queue build: nightly batch eval 5/5 (pass_rate 1.0); an inline ingest of 40 documents blocks the handler 17,305 ms; a flaky corpus succeeds on attempt 2; a corrupt corpus is dead-lettered after 4 attempts; re-ingesting 100 documents indexes 0 new.

## Stack
Python, FastAPI, Pydantic, OpenAI SDK with `gpt-5.4-mini-2026-03-17`, Celery + Redis, OpenTelemetry SDK, SQLite, Docker, GitHub Actions, pytest.
