# W3 · TicketStream

## What it is
TicketStream turns a free-text support message into a validated ticket, streams the ticket fields to the client, and routes it to a team queue. A side effect runs only after the model output passes a strict schema check.

## How it works
- `POST /intake-stream` takes `message` and `provider` (`openai` = `gpt-5.4-mini-2026-03-17`, `nano` = `gpt-5.4-nano-2026-03-17`).
- The model is given one tool, `extract_ticket`, whose parameters are `TicketSchema.model_json_schema()`: a discriminated union intent (`order` with `order_id`, `refund` with `order_id` and a reason of 3+ chars, `billing` with `invoice_id`), priority `Literal["low","medium","high","critical"]`, optional `customer_id`, and `attachments`.
- `validate_and_correct()` runs `TicketSchema.model_validate` on the tool arguments. On a `ValidationError` it appends the validator errors as a `tool` message and calls again, at most 2 corrections (3 attempts). A prose answer stops with no retry.
- Only after validation does `intake_generator` emit SSE events `intent`, `priority`, `customer_id`, `routed`, `done`; a failure emits `validation_failed` then `done`.
- `team_for_intent` maps order to `fulfillment`, refund to `refunds`, billing to `billing` in code. `route_to_team` is never in the model's tool list and is wrapped in a tenacity retry: 3 attempts, 500 ms to 8 s backoff, only on httpx timeout or network errors.

## Key decisions
- **Validate first, stream second** - partial JSON cannot be validated, so fields are streamed from an already-validated ticket; nothing streams until extraction finishes.
- **Tool calling plus Pydantic, not provider strict mode** - portable across providers for later routing, at the price of needing the correction loop.
- **Hard cap of 2 corrections** - beyond that the schema or prompt needs fixing, not another call.
- **SSE, not WebSockets** - the flow is one-way and works over plain HTTP and curl; responses send `Cache-Control: no-cache` and `X-Accel-Buffering: no`.
- **Side-effect tool not model-facing** - application code decides when to route, so bad model output cannot trigger routing.

## Results
- No scored eval set this week; all 7 offline smoke tests in `tests/test_intake_stream.py` pass (e.g. `priority="urgent"` rejected, SSE events in order, failed validation emits only `validation_failed, done`).
- Worked example: `ORD-1042` is extracted as an order, priority high, `correction_count` 0.

## Stack
Python, FastAPI 0.115.6, OpenAI SDK 2.14.0 (`AsyncOpenAI`) with `gpt-5.4-mini-2026-03-17` / `gpt-5.4-nano-2026-03-17`, Pydantic 2.10.4, pydantic-settings, tenacity 9.0.0, httpx, pytest-asyncio.
