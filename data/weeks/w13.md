# W13 · WorkbenchAI™

## What it is
A streaming operator console for an ops assistant: the answer arrives token by token, interleaved with the runbook citations and tool calls behind it. A side-effecting action (restarting a service) waits for a human to approve it, and a thumbs-down or correction becomes an offline eval case.

## How it works
- `POST /chat/stream` is a FastAPI SSE generator emitting typed frames over one connection: `token`, `citation`, `tool_call`, `approval_required`, then `done`.
- The model gets a function-calling catalog generated from Pydantic input models and decides per question whether to call tools, for up to `MAX_TOOL_TURNS = 4` turns; an off-topic question gets zero tool calls.
- Tools: `search_runbook` (read-only keyword search over 4 markdown runbooks, at most 2 hits) and `restart_service` (gated, Literal-constrained service names).
- A `restart_service` request is parked as a `PendingAction` in an in-memory dict; only `POST /approve` (approve or deny, consumed once, unknown id -> 404) executes it.
- `POST /feedback` writes to SQLite; a thumbs-down or correction appends a BreakRAG-shaped `EvalSignal` (question, answer, correction, citation markers) to `eval_signals.jsonl`, readable at `GET /eval/signals`.
- A React (Vite) UI renders citation cards, a tool-trace accordion, an approval box and a feedback form.

## Key decisions
- **SSE, not WebSockets** - the answer is one-directional and SSE rides plain HTTP; no bidirectional channel is needed.
- **`fetch` + stream reader instead of `EventSource`** - a chat request needs a POST body; the cost is losing automatic reconnection.
- **One stream, four typed frames** - keeps citations, traces and approvals in causal order without coordinating separate endpoints.
- **The approval gate is server-side** - the browser only renders it; `/approve` itself is unauthenticated in this build, and parked actions do not survive a restart.

## Results
- No recorded eval run: this build ships no eval gate or scored set. Its 10 pytest tests (stubbed model) pin the frame contract, that `restart_service` never executes inside the stream, and that only a thumbs-down queues an eval signal; "10 passed" was shown in a live run, but no results file is committed.
- `week13_notebook.ipynb` saved outputs show the contract end to end - one live stream, an approved restart returning `restart_count: 1`, an empty question rejected with 422, an unknown action id refused with 404, and a thumbs-down returning `eval_signal_queued: true` - a demo, not a measurement.

## Stack
Python, FastAPI, Pydantic 2 + pydantic-settings, OpenAI SDK with `gpt-5.4-mini-2026-03-17`, stdlib sqlite3, React 18 + Vite 5, pytest.
