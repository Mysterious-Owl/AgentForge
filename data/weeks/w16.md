# W16 · CostGuard™

## What it is
CostGuard™ is a FastAPI service with two systems: a cost-aware router that sends each task to the cheapest model tier that can handle it and measures every dollar, and an event-driven SRE bot that diagnoses an alert and proposes a remediation that waits for human approval.

## How it works
- `POST /route`: a deterministic keyword-and-length classifier picks simple, medium or complex; below 0.60 confidence the router bumps one tier up. Tiers map to `gpt-5.4-nano-2026-03-17`, `gpt-5.4-mini-2026-03-17` and `gpt-5.4-2026-03-05`.
- Prices are keyed by model id, per 1M tokens: nano $0.20 in / $1.25 out, mini $0.75 / $4.50, gpt-5.4 $2.50 / $15.00, cached input a tenth; an unknown id is billed at the highest listed price.
- Before a call, `tiktoken` (`o200k_base`) prices the worst case against a $0.05 ceiling (413 if over); exact repeats come from a local cache at $0; every billed response carries `X-CostGuard-Cost-USD`, and `GET /report` rolls up the last 7 days against an all-frontier baseline.
- `POST /webhook/alert` verifies an HMAC signature, returns 202 with a receipt, dedupes by a service+description fingerprint (SQLite partial unique index on open actions) and diagnoses in the background with an LLM (rule-engine fallback), capped at 8 iterations.
- The proposed remediation is saved `pending`; `POST /approve` and `POST /undo` need a bearer token and an on-call email.

## Key decisions
- **Route up below 0.60** - a wrong cheap answer costs more than a right expensive one; it routes exactly the short-and-unclear branch up.
- **Bill by served model id, not tier label** - a silent re-pin shows up as vanished savings.
- **Count tokens with the tokenizer** - a characters-per-token guess undercounts dense text such as log dumps.
- **SQLite for paused actions** - durable across restarts with no server; the same index works on Postgres.

## Results
- Routing gate `eval_run.py` on the 10-case `data/routing_eval_set.json`, with a stub model whose token counts scale with prompt length: 10/10 correct (floor 0.9), $0.004559 routed vs $0.010722 all-frontier, 57.5% saved (floor 40%), no cache hits - recorded in `week16_notebook.ipynb` outputs and reproducible.
- Same notebook, failure runs: `ROUTE_UP_THRESHOLD=0` drops accuracy to 8/10 (FAIL); re-pinning the small tier to the frontier model cuts savings to 13.5% (FAIL).
- The 135-test suite (no key, no network) passed in a live run; no results file is committed.

## Stack
Python, FastAPI, Pydantic 2 + pydantic-settings, OpenAI SDK with `gpt-5.4-nano-2026-03-17` / `gpt-5.4-mini-2026-03-17` / `gpt-5.4-2026-03-05`, tiktoken, stdlib sqlite3, pytest.
