# W10 · TriageFlow™

## What it is
TriageFlow™ routes incoming IT incidents through three cooperating agents: a Triage classifier, a Knowledge agent that answers from runbooks with citations, and an Action agent that proposes infrastructure changes. Infrastructure changes wait for human approval, and per-user memory can be erased on request.

## How it works
- A LangGraph `StateGraph` with five nodes: `triage`, `knowledge`, `action`, `action_execute`, `compose`; the conditional edge `route_after_triage` sends a request to knowledge, action or escalation (falling back to knowledge on an unexpected value).
- `TriageState` is a `TypedDict` handoff contract; `assert_handoff` raises a `ValueError` naming the missing field at the knowledge, action and compose entries.
- The Action agent only proposes a JSON call to `restart_service`, `page_team` or `file_ticket` (all simulated). `interrupt_before=["action_execute"]` pauses the graph (in-process `MemorySaver` checkpointer); `POST /approve` resumes it and returns 409 if not paused there.
- Four memory layers, all written through `memory_write(scope, kind, payload)`: session on Redis (key `session:{user_id}:{thread_id}`, 1 h TTL), external runbooks and episodic incidents in a vector store, and procedural prefs in an in-process dict. Knowledge retrieves the top 5 runbook chunks and the top 3 prior incidents for that user.
- Vector search uses deterministic hashed bag-of-words embeddings with cosine top-k in process, or PostgreSQL 16 + pgvector with `MEMORY_BACKEND=pgvector`.
- Also `POST /prefs`, `DELETE /user/{user_id}` (erasure receipt), `GET /session/{thread_id}`, `GET /health`; recursion limit 10.

## Key decisions
- **LangGraph over a raw loop** - checkpointing and `interrupt_before` come built in; the cost is a framework dependency.
- **Propose, never execute** - the only execution point is `action_execute`, after approval.
- **Model tiering in config** - `gpt-5.4-nano-2026-03-17` for one-word triage (capped at 20 output tokens), `gpt-5.4-mini-2026-03-17` for knowledge and action answers; the escalate route makes only the nano call and returns a canned message.
- **One scoped write path** - one choke point asserting `global` or `user:{uid}` scope, preventing cross-tenant leaks.

## Results
- No scored eval set this week; all 19 offline tests in `tests/test_endpoint.py` (stubbed LLM and Redis) pass, covering routing, the approval gate and 409, handoff contracts, user-scoped episodic search, and the four-layer delete.
- `DELETE /user/u_1` returns a receipt of session 2, episodic 2, procedural 1, external 0; the global runbook corpus is untouched and the same knowledge request still answers afterwards.

## Stack
Python 3.10+, FastAPI, LangGraph 1.2.9, OpenAI SDK with `gpt-5.4-nano-2026-03-17` and `gpt-5.4-mini-2026-03-17`, tenacity, Redis, optional pgserver (PostgreSQL 16.2 + pgvector 0.6.2), LangSmith tracing (optional).
